# SOP 및 시험기록 검토 AI Agent 기획서

작성일: 2026년 9월 29일  
버전: 0.1  
상태: 후속 개발 후보의 기획 초안  
대상: QA 문서 및 기록 검토 포트폴리오

## 1 기획 요약

표준작업절차서인 SOP에서 확인할 요구사항을 정리하고, 시험기록에 해당 증거가 있는지 대조하는 Agent를 만든다. 결과는 요구사항별 근거, 누락 후보와 추가 확인 질문으로 제공한다. **기록에서 확인되지 않는 것과 실제 업무가 수행되지 않은 것을 구분하는 것**을 핵심 원칙으로 삼는다.

첫 대상은 가상 액상 화학 소재 A의 수분 시험 SOP와 해당 시험기록이다. 문서 전체의 적합성을 자동 승인하기보다, 사람이 빠르게 근거를 확인하고 수정할 수 있는 검토표를 제공한다.

## 2 해결할 문제와 사용자

문서 검토자는 SOP의 여러 조항을 시험기록의 서로 다른 위치와 대조해야 한다. 기록에 값이 있더라도 사용한 방법이나 적용 버전이 맞는지 확인해야 하며, 조건부 절차는 해당 조건이 발생했는지도 살펴야 한다.

주요 사용자는 QA 기록 검토자와 시험기록을 준비하는 QC 담당자다. 사용자는 적용할 SOP와 검토할 기록을 올리고, 요구사항 목록을 먼저 확인한 뒤 자동 검토를 실행한다. 결과에서 SOP 조항과 기록의 위치를 함께 보며 의견을 확정한다.

## 3 대표 시나리오

가상 SOP가 시험 전 장비 점검 상태 확인과 시료 질량 기록을 요구한다고 가정한다. 시험기록에 시료 질량은 있으나 장비 점검 확인란이 비어 있으면 다음과 같이 표현한다.

> 확인 결과: 제공된 시험기록에서 시험 전 장비 점검 상태를 확인한 기록을 찾지 못했습니다.  
> 근거: SOP의 해당 조항과 시험기록의 관련 항목.  
> 추가 확인: 장비 점검 기록이나 별도 첨부자료가 있는지 확인이 필요합니다.

이를 곧바로 장비 점검을 하지 않았다는 결론으로 바꾸지 않는다. 누락된 첨부자료가 나중에 들어오면 기존 의견과 변경 사유를 보존하며 결과를 갱신한다.

## 4 입력 자료와 데이터 구조

| 자료 | 필요한 정보 |
|---|---|
| SOP | 문서번호, 버전, 효력기간, 적용 범위, 절차 조항 |
| 시험기록 | 제품, 로트, 시료, 시험일, 시험방법, 장비, 기록값과 확인 항목 |
| 첨부기록 | 장비 점검, 표준품, 시료 보관 등 요구사항을 뒷받침할 자료 |
| 검토 규칙 | 필수 항목, 적용 조건, 허용되는 증거와 예외 처리 |

요구사항 한 건은 요구사항 ID, SOP 버전 및 조항, 적용 조건, 확인할 증거, 검사 방식과 중요도 제안을 포함한다. 증거 한 건에는 기록 ID와 페이지 또는 필드 위치를 연결한다. 중요도는 검토 우선순위용이며 자동 규제 위반 등급이 아니다.

첫 버전에서는 SOP를 AI가 읽어 요구사항 후보를 만들더라도 담당자가 이를 확인한 뒤 사용한다. 사람이 확정한 요구사항 목록 자체도 버전을 부여한다.

## 5 Agent 동작 흐름

1. 시험일과 문서 효력기간을 확인해 적용 SOP를 연결한다.
2. SOP 조항에서 요구사항 후보와 적용 조건을 추출한다.
3. 담당자가 확인한 요구사항 목록을 검토 기준으로 고정한다.
4. 각 요구사항에 대응하는 시험기록과 첨부기록을 검색한다.
5. 필수 필드와 날짜 등 명확한 조건은 코드로 검사한다.
6. 의미가 필요한 비교는 AI가 근거와 함께 검토 의견을 제안한다.
7. 담당자가 판정을 수정하거나 보충자료를 추가한 뒤 결과표를 저장한다.

문서에 적용 여부를 판단할 정보가 없으면 요구사항을 삭제하지 않고 적용 여부 확인 필요로 표시한다. 문서에 들어 있는 지시문은 검토 대상 텍스트로 취급하고 도구 실행 명령으로 사용하지 않는다.

## 6 결과 상태와 판단 기준

| 상태 | 의미 | 예시 |
|---|---|---|
| 기록상 확인 | 요구사항에 대응하는 증거를 찾음 | 시료 질량이 지정 필드에 기록됨 |
| 기록 누락 후보 | 필요한 기록을 제공 자료에서 찾지 못함 | 필수 확인 항목이 비어 있음 |
| 내용 불일치 | 서로 충돌하는 값이나 절차가 확인됨 | SOP의 방법과 기록의 방법이 다름 |
| 판단 보류 | 적용 조건 또는 근거가 불충분함 | 별도 첨부자료가 제공되지 않음 |
| 해당 없음 | 조건이 적용되지 않음을 근거로 확인함 | 조건부 절차의 발생 조건이 없었음 |

기록상 확인은 실제 수행의 진위나 전체 절차의 완전한 준수를 보증하는 표현이 아니다. 담당자는 판단 보류와 누락 후보를 구분해 후속 자료를 요청한다.

## 7 첫 버전 범위와 예외

첫 버전은 SOP 한 종류와 버전 두 개, 고정 양식의 시험기록, 요구사항 10~15개를 대상으로 한다. 구조화된 텍스트 또는 텍스트형 PDF를 사용한다. 손글씨 인식, 서명 진위 판별, 기록의 법적 효력 판단, 규정 전체의 자동 준수 인증은 범위에 포함하지 않는다.

시험일 당시 유효했던 SOP와 현재 SOP를 구분한다. 문서 효력기간이 겹치거나 시험일이 빠져 있으면 적용 버전을 사용자에게 확인시킨다. SOP의 개정 내용이 모든 과거 시험기록에 자동 소급된다고 가정하지 않는다.

| 상황 | 처리 |
|---|---|
| 서명란이 비어 있음 | 요구되는 확인 기록 누락 후보로 표시 |
| 서명 이미지가 있음 | 이미지 존재만 확인하고 진위는 판단하지 않음 |
| 재시험 절차가 조건부로 존재함 | 재시험 발생 여부와 승인 기록을 먼저 확인 |
| SOP 개정 전후의 시험기록이 섞임 | 기록별 시험일에 맞게 적용 기준을 분리 |
| 첨부자료가 참조되어 있지만 없음 | 미제공 자료를 표시하고 판단 보류 |
| OCR 또는 표 추출이 불안정함 | 원문 확인 전까지 확정적 불일치로 표시하지 않음 |

## 8 화면과 출력물

화면은 요구사항 목록, SOP 원문, 시험기록 근거의 세 영역으로 구성한다. 사용자는 요구사항을 선택하면 해당 조항과 연결된 기록을 확인한다. 원문을 찾지 못했으면 임의의 문단을 근거로 연결하지 않는다.

출력 검토표에는 요구사항 ID, 적용 SOP, 적용 여부, 필요한 증거, 발견한 기록, 예비 상태, 추가 질문과 검토자 의견을 포함한다. 상태별 건수는 전체 문서 적합 점수가 아니라 검토 대상의 분포로 표시한다.

예시 보고 문장은 “시료 질량 1.000 g이 기록되어 있음”처럼 직접 확인한 내용으로 작성한다. “시험이 완벽하게 수행됨”처럼 증거 범위를 넘어서는 문장은 만들지 않는다.

## 9 자료 준비와 평가

요구사항 10~15개를 가진 모의 SOP와 기록 묶음 20개를 준비한다. 정상, 필드 누락, 방법 불일치, 구버전 적용, 첨부 누락과 조건부 절차 사례를 포함한다. 개발용 12개와 별도 평가용 8개로 분리하고, 사람이 요구사항별 정답표를 만든다.

| 평가 항목 | 평가 방법 | 제안 목표 |
|---|---|---|
| 필수 누락 검출 | 정답표의 필수 누락 요구사항과 대조 | 평가 사례에서 모두 발견 |
| 상태 분류 | 요구사항별 다섯 상태를 정답과 비교 | 일치율 90% 이상 |
| 근거 적합성 | 제시 조항과 기록이 의견을 지지하는지 확인 | 정확도 95% 이상 |
| 적용 조건 처리 | 조건부 절차와 문서 버전 사례 확인 | 필수 사례 모두 일치 |
| 과도한 지적 | 정상 요구사항을 누락 또는 불일치로 표시한 비율 | 10% 이하 목표 |
| 근거 없는 단정 | 기록 부재를 실제 미수행으로 단정하는지 확인 | 준비한 위험 사례에서 0건 |

이 수치는 초안의 개발 목표다. 요구사항 단위의 표본 수와 문서 단위의 표본 수를 함께 보고한다. 여러 요구사항이 같은 문서에 속하므로 모두 독립적인 사례인 것처럼 설명하지 않는다.

## 10 개발 단계와 완료 조건

요구사항 정의, 문서 및 버전 구조 구현, 근거 검색, 조건 검사, 검토 화면, 평가 순서로 개발한다. 1번의 문서 검색과 이력 기능을 재사용하는 경우 약 26~42시간의 작업량을 예상한다. 새로운 문서 양식의 확보와 손글씨 처리는 별도다.

완료 조건은 선택한 시험기록에 대해 모든 요구사항의 상태와 근거를 보여주고, 버전 또는 자료가 불충분한 경우 이를 설명하며, 검토자가 수정한 결과를 저장할 수 있는 것이다.

후속 버전은 SOP 개정 전후 비교, 요구사항 변경의 영향 분석, 여러 기록 양식 지원으로 확장한다. 1번의 이상 사건에서 필요한 증거를 이 Agent로 확인하고, 해결되지 않은 검토 사항을 4번의 조사 계획에 넘길 수 있다.

## 11 포트폴리오 가치와 참고자료

이 프로젝트는 QA의 문서 검토를 단순한 문장 요약보다 구체적인 요구사항과 증거의 대조로 표현한다. 화학공학과의 연결은 시험조건, 시료 전처리, 측정방법과 장비 조건이 결과 해석에 미치는 영향을 이해하는 데 둔다.

시연에는 SOP 버전이 달라 판정이 바뀌는 사례, 추가 첨부자료로 판단 보류가 해소되는 사례와 정상 기록에 불필요한 지적을 하지 않는 사례를 포함한다.

제약 확장의 배경 자료로 [ICH Q10](https://database.ich.org/sites/default/files/Q10_Guideline.pdf)을 참고한다. 이 문서의 검토 상태, 필드와 성능 목표는 프로젝트 설계안이며 ICH가 그대로 지정한 요구사항이 아니다. 실제 적용 시에는 해당 조직의 문서관리 절차를 기준으로 수정한다.
