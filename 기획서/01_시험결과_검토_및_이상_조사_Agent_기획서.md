# 시험결과 검토 및 이상 조사 보조 AI Agent 기획서

작성일: 2026년 9월 29일  
버전: 0.1  
상태: 우선 개발할 프로젝트의 기획 초안  
대상: 화학공학 전공자의 QC 및 QA 직무 포트폴리오

## 1 기획 요약

시험결과 파일을 입력하면 제품 규격과 대조하고, 검토가 필요한 결과에 대해 관련 절차와 확인할 기록을 찾아 조사보고서 초안을 작성하는 Agent를 만든다. 첫 버전은 제품 하나와 시험항목 세 개를 대상으로 한다. **계산 결과를 재현할 수 있고, AI가 제시한 내용의 근거를 확인할 수 있는 것**을 핵심 가치로 삼는다.

첫 개발 대상은 가상의 액상 화학 소재 A다. 수분, 주성분 함량과 점도 데이터를 활용해 화학공학의 공정 이해와 QC의 시험결과 검토, QA의 기록 및 조사 업무를 연결한다. 아래 수치와 사례는 교육용으로 설계한 값이며 실제 제품 규격이 아니다.

## 2 해결하려는 문제와 사용자

시험 담당자는 시험값을 규격서와 대조하고, 이상 결과가 있으면 해당 SOP와 장비 및 공정 기록을 다시 확인해야 한다. 서로 다른 파일을 오가면서 항목을 놓치거나, 근거 없이 원인을 추정하거나, 조사 내용을 정리하는 데 시간이 들 수 있다. 프로젝트에서는 이 과정을 하나의 검토 흐름으로 묶는다.

| 사용자 | 수행할 업무 | 제공할 도움 |
|---|---|---|
| QC 시험 담당자 | 시험결과와 규격을 대조 | 계산 가능한 비교 결과와 오류 위치 표시 |
| QC 검토자 | 이상값과 관련 기록을 확인 | 필요한 근거와 추가 확인 질문 정리 |
| QA 담당자 | 조사 내용과 기록을 검토 | 사실과 가설이 분리된 보고서 초안 제공 |
| 포트폴리오 평가자 | 구현 역량과 직무 이해를 확인 | 입력부터 판단 근거까지 재현 가능한 시연 |

## 3 사용 시나리오

사용자가 시험결과 CSV를 올리고 제품 규격 버전을 선택한다. Agent는 누락 필드와 단위를 확인한 다음, 비교 가능한 행만 계산한다. 이상 항목을 선택하면 관련 SOP 조항과 조사 질문을 보여주고, 사용자가 추가한 기록을 반영해 보고서 초안을 만든다.

예를 들어 수분 규격이 500 ppm 이하이고 결과가 620 ppm이면, 규격 상한을 120 ppm 초과한 사실을 표시한다. 건조 부족을 확정하지 않고 시료 보관, 측정 기록, 건조 온도 및 시간 기록 등 확인할 대상을 제안한다. 기록에서 실제로 확인된 내용만 사실 항목으로 옮긴다.

결과값이 비어 있거나 ppm의 기준이 질량인지 부피인지 알 수 없다면 규격 내 결과로 처리하지 않는다. 비교 불가 사유와 필요한 입력을 제시한다.

## 4 첫 버전의 범위

| 구분 | 포함 기능 | 완료 상태 |
|---|---|---|
| 입력 | 고정 양식 CSV 업로드와 필드 검증 | 잘못된 행과 사유가 표시됨 |
| 규격 | 버전이 있는 제품 규격을 선택하고 대조 | 규격 내, 규격 외, 판정 불가로 구분됨 |
| 추세 | 로트별 시험값을 시간순으로 표시 | 규격선과 원본 값이 확인됨 |
| 조사 | 시험항목에 맞는 SOP 검색과 질문 제안 | 문서 버전 및 조항이 연결됨 |
| 문서 | 검토보고서 초안 생성 및 다운로드 | 수치와 근거가 원본까지 추적됨 |
| 기록 | 실행 입력, 사용 규칙, 검토 의견 보관 | 동일 입력으로 계산 결과를 재현함 |

첫 버전의 추세 화면은 변화 양상을 보여주는 용도다. 통계적 이상 경보는 다음 버전에서 추가한다. 장비 원시 신호나 크로마토그램 해석, 자동 재시험, 생산 시스템 연결, 출하 승인과 원인 확정은 초기 범위에서 제외한다.

## 5 데이터 설계

### 5 1 시험결과의 단위와 필드

시험결과 한 행은 **특정 로트의 특정 시료에 대한 시험항목 한 번의 측정 결과**다. 재측정과 반복 측정은 각각 별도 행으로 보관한다. 로트와 시험항목만 같다는 이유로 중복으로 삭제하거나 평균하지 않는다.

| 필드 | 내용 | 처리 원칙 |
|---|---|---|
| result_id | 측정 결과 고유번호 | 같으면 중복 여부 확인 |
| product_id, lot_id | 제품과 제조 로트 | 누락 시 규격 대조 보류 |
| sample_id, replicate_no | 시료와 반복 측정 번호 | 반복 측정의 의미 보존 |
| test_code | 표준 시험항목 코드 | 등록된 항목과만 매핑 |
| result_raw, value, qualifier | 원문, 수치, 부등호 등 | 원문과 해석값을 함께 저장 |
| unit, basis | 단위와 질량 또는 부피 기준 | 확인된 변환만 허용 |
| method_id, method_version | 시험방법과 버전 | 비교할 규격의 방법과 대조 |
| measured_at, condition | 측정 시각과 온도 등 조건 | 시간순 정렬 및 비교 조건 확인 |
| instrument_id | 장비 식별자 | 조사 기록과 연결 |
| source_file, source_row | 입력 파일과 행 번호 | 결과에서 원본으로 이동 |

규격은 제품, 시험항목, 시험방법, 단위, 측정 조건, 상한과 하한, 경계 포함 여부, 버전, 효력 시작일과 종료일을 저장한다. 시험일에 적용된 규격을 선택하고, 현재 규격과의 추가 비교가 필요하면 별도 결과로 표시한다. 적용 버전이 여러 개이거나 유효기간이 겹치면 자동 선택하지 않는다.

### 5 2 학습용 제품 규격

| 시험항목 | 가상 기준 | 단위와 조건 |
|---|---|---|
| 수분 | 500 이하 | ppm, 질량 기준 |
| 주성분 함량 | 99.5 이상 | %, 질량 기준 |
| 점도 | 20.0 이상 30.0 이하 | mPa·s, 25 °C, 지정 시험방법 |

표의 모든 경계값은 포함한다. 보고된 유효 숫자와 별도의 반올림 규칙은 규격 설정에 기록한다. 오차 허용범위나 임의의 반올림으로 규격 외 결과를 규격 내로 바꾸지 않는다. 실제 제품에 적용할 때는 해당 시험방법과 승인된 판단 규칙을 확인한다.

### 5 3 준비할 자료

- 기본 데이터: 100개 로트, 로트당 세 항목으로 구성한 300행의 모의 시험결과.
- 규격: 위 가상 규격 한 버전과 버전 변경 검증용 규격 한 버전.
- SOP: 수분, 함량, 점도 시험 관련 문서와 이상 결과 검토 절차 등 4~5개 문서.
- 조사 기록: 장비 점검, 시료 보관, 공정 조건을 담은 짧은 모의 기록.
- 별도 평가 세트: 경계값, 누락, 단위 불일치, 버전 충돌 등을 포함한 30개 검토 사례.

평가 세트와 정답표는 개발용 예시와 분리한다. 정답표에는 기대 상태, 비교에 사용한 규격, 필요한 질문과 허용 가능한 근거 문서를 기록한다. 예시 데이터의 첫 40개 로트는 후속 관리도 실습의 기준 후보로 별도 표시하되, 기준 데이터로 사용할지는 검토 후 결정한다.

## 6 Agent의 동작과 도구

Agent는 대화만 생성하는 기능에 그치지 않고, 필요한 도구를 순서대로 호출하고 불완전한 입력이 있으면 해당 단계에서 확인을 요청한다. 첫 버전은 한 개의 Agent와 명시적인 작업 단계로 구현한다.

| 단계 | 도구 역할 | 결과 또는 분기 |
|---|---|---|
| 1 입력 검사 | 필수 필드, 숫자 형식, 단위, 중복 후보 검사 | 오류 행과 비교 가능한 행을 구분 |
| 2 규격 연결 | 제품, 방법, 날짜에 맞는 규격 검색 | 유일하게 연결되지 않으면 판정 보류 |
| 3 규격 비교 | 경계 포함 여부를 반영해 코드로 계산 | 규격 내, 규격 외, 판정 불가 |
| 4 근거 검색 | 해당 항목과 사건에 맞는 SOP 문단 검색 | 문서명, 버전, 조항, 발췌 위치 반환 |
| 5 조사 제안 | 확인된 사실과 검색 근거를 바탕으로 질문 생성 | 가설, 필요한 증거, 다음 확인사항 |
| 6 초안 작성 | 구조화된 결과로 보고서 생성 | 계산값과 근거가 연결된 초안 |
| 7 검토 반영 | 검토자가 수정한 내용과 사유 저장 | 검토 이력이 포함된 최종 초안 |

AI가 출력한 수치가 계산 결과와 다르면 계산 결과를 기준으로 보고서 생성을 중단하고 불일치를 표시한다. 검색한 문서에 관련 근거가 없으면 조항을 만들어내지 않고 근거 부족으로 표시한다. 외부 문서의 문장을 시스템 명령으로 실행하지 않도록 문서 내용과 도구 실행 지시를 분리한다.

## 7 판정과 예외 처리

### 7 1 세 가지 기본 상태

- **규격 내:** 입력과 적용 규격이 충분하고, 비교 결과가 허용 범위 안에 있음.
- **규격 외:** 입력과 적용 규격이 충분하고, 비교 결과가 허용 범위 밖에 있음.
- **판정 불가:** 결과 누락, 해석 불가, 단위 기준 불명, 방법 불일치 또는 규격 버전 충돌 등으로 비교할 수 없음.

데이터 오류는 별도 경고로 표시한다. 서로 다른 반복 측정 결과가 있을 때 유리한 결과만 선택하지 않고 전체 기록을 보여준다. 로트 전체의 출하 적합성은 이 세 상태로 자동 결론 내리지 않는다.

### 7 2 반드시 다룰 예외

| 상황 | 처리 |
|---|---|
| 수분 결과가 500 ppm | 경계를 포함하므로 해당 항목은 규격 내 |
| 수분 결과가 500.1 ppm | 정해진 보고값 규칙에 따라 비교하며 임의로 내림하지 않음 |
| 수분 결과가 0.062% 질량 기준 | 단위 변환이 승인된 설정이면 620 ppm으로 변환하고 기록 |
| ppm의 질량 또는 부피 기준이 없음 | 확인 전까지 판정 불가 |
| 결과가 ND 또는 검출한계 미만 | 첫 버전에서는 정량값으로 치환하지 않고 수동 검토 |
| 점도 측정 온도가 누락됨 | 규격의 조건 충족 여부를 확인할 때까지 판정 불가 |
| 같은 result_id에 다른 값이 있음 | 충돌 표시 후 두 원본을 유지 |
| 재시험값만 규격 내임 | 최초 결과와 함께 표시하고 자동 대체하지 않음 |
| 근거 문서가 폐기되었거나 버전이 모호함 | 유효한 근거가 확정될 때까지 조사 의견에 표시 |

## 8 화면과 보고서

### 8 1 화면 구성

1. **입력 화면:** 제품 선택, 시험결과 업로드, 사용 규격 표시, 입력 오류 확인.
2. **검토 화면:** 상태별 건수, 항목별 비교표, 시간순 추세, 원본 행과 적용 규격 확인.
3. **조사 화면:** 사건 선택, 관련 SOP 문단, 추가 기록 입력, 사실 및 가설 검토.
4. **보고서 화면:** 초안 수정, 근거 확인, 검토자 메모, 파일 다운로드.

상태는 색상뿐 아니라 텍스트로도 표시한다. 추세 차트에서는 규격 상한과 하한을 명확히 표시하며, 아직 계산하지 않은 관리한계선을 규격선처럼 표시하지 않는다.

### 8 2 보고서 구성

- 검토 대상: 제품, 로트, 시료, 시험항목, 입력 파일과 실행 시각.
- 적용 기준: 규격 및 시험방법의 버전, 단위와 측정 조건.
- 확인된 결과: 시험값, 기준값, 차이와 예비 상태.
- 근거: 원본 행, 관련 문서와 조항, 추가 확인한 기록.
- 미확인 사항: 판단에 필요한 누락 정보와 요청할 기록.
- 조사 가설: 가능한 설명, 뒷받침하는 자료, 반대 증거와 검증 방법.
- 검토 의견: 담당자의 수정 내용, 사유와 후속 업무.

초기 다운로드 형식은 읽기 쉬운 Markdown 또는 HTML을 사용한다. Word와 PDF 출력은 이후 확장한다.

## 9 구현 구조와 비용 관리

첫 구현은 Python 기반의 단일 애플리케이션을 권장한다. 화면, 입력 검증, 규격 비교, 문서 검색, 보고서 생성 기능을 모듈로 나눈다. 규격과 실행 이력은 SQLite 같은 경량 저장소에 두고, 원본 파일은 변경하지 않은 채 보관한다. 개발 편의에 따라 화면 프레임워크는 구현 시작 시 선택한다.

문서가 4~5개일 때는 제목과 시험항목 중심의 단순 검색으로 시작할 수 있다. 문서 수가 늘면 문단을 검색해 AI에 전달하는 RAG 방식을 추가한다. 처음부터 별도의 벡터 데이터베이스나 복잡한 다중 Agent 구조를 필수로 삼지 않는다.

LLM은 조사 질문과 보고서 초안 생성에 사용한다. 호출에 실패해도 계산된 비교표는 볼 수 있게 하고, AI 생성 부분만 대기 상태로 표시한다. 같은 검색 결과를 재사용하고, 원문 전체 대신 필요한 문단만 전달하며, 실행별 호출 횟수와 사용량을 기록한다. 사용할 모델과 실제 요금은 개발 시작 시 확인하고 예산 상한을 설정한다.

원본 해시, 규격 버전, 규칙 버전, 모델 식별자, 프롬프트 버전과 검토 이력을 기록한다. 로컬 파일의 해시와 로그만으로 변경 불가능한 감사추적이나 규제 적합성이 확보되었다고 주장하지 않는다.

## 11 평가 방법과 완료 조건

평가 지표는 제안 목표이며, 실제 측정 결과는 개발 후 별도로 기록한다. 비교 규칙의 정답은 AI가 만든 답을 그대로 사용하지 않고 직접 검토한 정답표로 고정한다.

| 평가 항목 | 평가 방법 | 첫 버전 목표 |
|---|---|---|
| 규격 비교 | 경계 포함, 상하한, 변환을 포함한 결정적 사례 대조 | 준비한 필수 사례 모두 일치 |
| 입력 오류 | 누락, 충돌, 모호한 단위 사례 확인 | 필수 오류 사례가 규격 내로 표시되지 않음 |
| 규격 외 검출 | TP를 실제 규격 외 건수로 나눈 재현율 산출 | 평가 세트 재현율 100% 목표 |
| 잘못된 경고 | 정상 데이터에 대한 오탐 건수 기록 | 평가 세트의 결정적 비교 오탐 0건 목표 |
| 근거의 적합성 | 인용한 조항이 바로 앞 주장을 지지하는지 검토 | 인용 정확도 95% 이상 목표 |
| 근거 부족 처리 | 관련 SOP가 없는 사례를 별도로 입력 | 없는 조항을 생성하지 않음 |
| 보고서 일관성 | 원본, 계산표, 보고서의 값과 단위 대조 | 수치 불일치 0건 목표 |
| 검토 시간 | 동일한 난이도의 별도 사례로 수작업과 보조 작업 비교 | 수정 시간을 포함해 전후 차이 보고 |

재현율과 오탐은 비교 가능한 행을 기준으로 산출하고, 판정 불가 비율도 함께 공개한다. 모든 어려운 사례를 판정 불가로 보내 성능이 좋아 보이게 하지 않는다. 인용 검토는 최소 20개 주장과 근거 쌍을 대상으로 하며, 표본 수와 오류 유형을 공개한다.

LLM의 변동성을 보기 위해 근거 부족 및 원인 단정 위험 사례는 같은 조건으로 세 번 실행한다. 작은 모의 평가 세트의 성공을 실제 현장 전체의 정확도로 일반화하지 않는다.

**첫 버전 완료 조건:** 준비한 파일을 올려 규격 비교표와 원본 근거가 연결된 조사보고서 초안을 생성하고, 예외 사례에서 판정 불가를 설명하며, 평가표와 시연 영상을 남길 수 있다.

## 12 다음 버전과 다른 Agent와의 연결

다음 버전에는 동일 제품, 시험방법과 조건의 안정적인 과거 데이터를 검토한 뒤 관리도를 추가한다. 로트당 대표 측정값이 하나이고 독립성 등 전제가 적절하면 I MR 관리도를 후보로 검토한다. 반복 측정이나 부분군이 있으면 데이터 구조에 맞는 관리도를 다시 선택한다. 기준 기간과 계산 방법을 고정하고 평가 대상 데이터를 섞어 관리한계를 매번 다시 맞추지 않는다.

규격선은 제품의 허용 기준이고 관리한계선은 기준 공정의 변동을 바탕으로 정하는 선이다. 관리한계를 벗어났다는 사실만으로 규격 외라고 부르지 않는다. 관리도는 공정 특성의 시간 변화와 관리한계를 활용하는 도구다. [NIST 관리도 설명](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc31.htm)

2번 Agent는 성적서에서 추출한 시험값을 같은 규격 비교 도구에 전달한다. 3번은 조사에 필요한 절차 및 기록의 연결을 강화한다. 4번은 검토된 사건과 근거를 받아 CAPA 계획을 작성한다.

제약 분야로 확장할 때는 OOS 조사 흐름을 별도로 검토한다. FDA 자료는 제약용 규격 외 시험결과의 평가에 관한 참고자료이며 일반 화학 소재의 모든 판단에 적용되는 기준은 아니다. [FDA OOS 지침](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/investigating-out-specification-oos-test-results-pharmaceutical-production-level-2-revision)

## 13 포트폴리오에서 보여줄 내용

정상 사례, 규격 외 사례, 판정 불가 사례의 시연을 각각 준비한다. 시연에서는 시험값이 어디서 왔는지, 어떤 규격을 적용했는지, 왜 특정 기록을 확인하라고 제안했는지 보여준다. 결과 화면뿐 아니라 오류 사례와 수정 과정을 함께 제시한다.

화학공학 역량은 수분 변화와 건조 조건, 함량 변화와 조성 또는 혼합 기록, 점도 변화와 측정 온도 등의 관계를 **확인할 가설과 필요한 데이터**로 설명하는 데서 드러낸다. 상관관계만으로 공정 원인을 확정하지 않는다.

최종 포트폴리오 묶음은 실행 방법, 모의 데이터 설명, 시스템 흐름도, 평가 결과, 대표 보고서와 짧은 시연 영상으로 구성한다. 산업군, 화면 도구와 사용할 AI 모델은 구현 전에 조정할 수 있지만, 위의 첫 버전 범위는 그대로 출발점으로 사용할 수 있다.
