# 점도 검토실 v0.1

**배포 주소:** [점도 검토실 열기](https://polymer-viscosity-review-kina2002.sooyeon-jun-0389.chatgpt.site)

다른 노트북에서도 로그인 없이 주소를 열어 사용할 수 있습니다. 링크를 가진 누구나 접근 가능한 Sites 공개 배포입니다. 기준·메모·체크 상태는 각 브라우저에 저장되며 기기 사이에 자동 공유되지 않습니다. [배포와 저장 안내](docs/배포_안내.md)를 참고하세요.

## 실행과 구조

웹 배포용 파일은 `npm run build:web`으로 생성합니다. `dist/`에는 화면·코드·가상 데이터 6개 파일만 들어갑니다. `.openai/hosting.json`은 Sites 배포 대상과 정적 파일 경로를 기록합니다. 배포 파일은 Git에서 제외하고, 같은 소스 커밋으로 다시 생성합니다.

서버 없이 사용하려면 이 폴더의 **점도_검토실_바로열기.html**을 Chrome이나 Edge에서 여세요. 데이터와 코드가 들어 있는 단일 파일이며 CSV 양식 다운로드도 서버 연결 없이 작동합니다. 파일을 다른 컴퓨터로 복사해서도 볼 수 있습니다. 기준·메모는 여전히 브라우저별로 저장되며 서버 버전의 저장 내용과 자동 공유되지 않습니다.

소스를 수정한 뒤 단일 파일을 갱신하려면 `npm run build:portable`을 실행하세요. 합성 데이터를 재생성했을 때도 같은 명령으로 갱신합니다.

아래 명령은 개발용 로컬 서버를 실행합니다.

```powershell
npm start
```

주소: http://127.0.0.1:4173. 기본 서버는 이 컴퓨터에서만 접근 가능한 `127.0.0.1`에 바인딩합니다. 다른 포트가 필요하면 PowerShell에서 `$env:PORT = '4174'`로 설정한 뒤 실행합니다.

## 사용 방법

상단 집계와 확인 항목 건수는 **전체 데이터** 기준입니다. 표·그래프·다운로드는 **현재 검색·필터** 기준입니다. 범주별 건수는 중복될 수 있습니다.

그래프의 점은 개별 측정값입니다. 가로축은 입력 데이터에 나타난 배치 순서이며 시간축이나 관리도가 아닙니다. 점선은 가상 규격 상하한입니다. 체크박스는 측정 조건 확인이 필요한 값을 제외합니다. 제조 기록 차이가 있는 값은 측정 방법 조건을 충족하면 표시될 수 있으며, 그래프만으로 품질을 판단하지 않습니다.

반복 측정마다 고유 측정 번호를 부여합니다. 같은 배치의 다른 측정값도 상세 화면에서 확인할 수 있습니다. 연속 운전 중 시간별 읽기와 독립 반복 측정은 별개이며, 이번 입력은 독립 측정 기록만 다룹니다.

그래프의 점을 누르면 해당 **측정 번호**를 선택하고 상세 기록으로 이동합니다. 표도 해당 기록이 있는 페이지로 바뀌며 검색·필터는 유지합니다. 선택한 점은 테두리로 표시합니다. 키보드로 점에 초점을 맞춘 뒤 **Enter 또는 Space**를 눌러도 이동할 수 있습니다.

### 실험 기록과 기준을 한눈에 비교하기

**실험 기록 ↔ 검토 기준** 비교표는 처음에 접혀 있습니다. 제목이나 **펼치기**를 누르면 열리고, **접기**를 누르면 아래 체크리스트를 바로 볼 수 있습니다. 같은 탭에서 다른 측정 기록을 선택하거나 기준을 바꿔도 현재 펼침 상태를 유지하며, 새로고침하면 다시 접힌 상태로 시작합니다. 키보드 Enter·Space로도 접거나 펼칠 수 있습니다.

선택한 측정의 상단에는 **먼저 이 값을 비교하세요** 안내가 나옵니다. 확인이 필요한 항목의 이름과 **실험 기록 ↔ 비교할 기준**을 함께 표시합니다. 차이가 없는 기록에서는 점도·측정 온도·측정 속도를 안내합니다. 확인 항목이 많으면 처음 4개를 먼저 보여주고 나머지는 펼쳐 볼 수 있습니다. 기준을 수정하면 안내도 함께 갱신됩니다.

측정 번호를 누르면 **실험 기록 ↔ 검토 기준** 표에 40개 항목이 나옵니다. 점도 결과, 측정 조건, 제조 조건, 나머지 기록 순서로 **항목 / 실험 기록 / 검토 기준 / 확인 결과**를 같은 행에서 비교합니다. 차이·누락·입력 문제는 색과 문구로 함께 표시합니다.

**확인할 항목만 보기**를 체크하면 확인이 필요한 행만 남습니다. **기준 수정**에서 기준을 바꾸면 표의 기준 값과 확인 결과도 즉시 갱신됩니다. 누락된 값도 원래 비교 기준과 나란히 표시합니다. 비교 기준이 없는 항목은 **기록 있음**으로 표시하며, 기준을 충족했다고 판정하지 않습니다. 작은 화면에서는 각 항목의 기록과 기준을 나란히 배치한 카드로 보여줍니다.

## 추가 확인 질문과 체크리스트

선택한 측정의 **다음 확인 질문 · 체크리스트**에서 현재 발견한 누락·입력 문제·측정 조건 차이·점도 이탈·제조 조건 차이에 맞는 질문을 읽습니다. 원본 자료를 확인한 항목은 **자료 확인 완료**에 체크합니다. 자료가 없거나 확인할 수 없다면 그 아래 **확인 불가**를 누르고 항목별 이유 입력칸에 기록합니다. 확인 불가를 다시 누르면 미확인으로 돌아갑니다. 확인 완료와 확인 불가는 동시에 표시되지 않습니다. 차이·누락이 없는 기록에는 자동 질문을 만들지 않습니다.

자료 확인 상태는 판정 변경이나 출하 승인이 아닙니다. 데이터별·측정별로 저장하고, 원본 기록 또는 기준이 저장 당시와 다르면 이전 상태를 적용하지 않습니다. 결과 CSV의 `followUpChecklist` 열과 TXT·Markdown 보고서에 질문·근거·상태·확인 불가 이유가 포함됩니다. CSV의 상태 키는 `pending`(미확인), `done`(자료 확인 완료), `unavailable`(확인 불가)입니다. 이전 버전의 체크는 확인 완료로 읽습니다. 확인 불가 이유가 비어 있으면 보고서에 미기재로 표시됩니다. [합의한 검토 원칙](docs/검토_원칙.md)을 참고하세요.

측정 온도 질문의 뜻은 **① 원본에도 그 온도가 기록돼 있는지 확인 → ② 실제 측정 온도가 기준과 달랐다면 기준 온도에서 다시 측정할 필요가 있는지 검토**입니다. 예를 들어 `PA-006-M1`은 실제 기록 28℃와 가상 기준 25 ± 0.5℃를 비교합니다. 온도가 다르다는 표시만으로 불량이나 재측정 필수를 확정하지 않습니다.

`PA-008`처럼 현재 기준에서 **점도 이탈만 발견된 기록**에는 제조·측정 조건 차이가 발견되지 않았고, 현재 기록만으로 원인을 알 수 없어 추가 자료가 필요하다고 안내합니다. 원본 측정 기록과 같은 배치의 반복값을 확인하고, 필요한 자료가 없으면 **확인 불가**와 이유를 기록합니다. 조건 차이·누락·입력 문제가 함께 있으면 기존 확인 흐름을 따릅니다. 해당 질문이 바뀌었으므로 점도 이탈만 있는 기록의 이전 체크는 미확인으로 표시하며, 다른 유형의 체크는 유지합니다. PA-008의 값은 범위 이탈 표시를 검증하기 위한 합성 값이며 조건에 따른 물성 예측이 아닙니다.

## 확인 불가 이유 분류와 모아보기

확인 불가를 누르면 **이유 분류**를 선택하고 그 아래에 메모를 남길 수 있습니다. 기본 분류는 **원본 기록 없음 · 필요한 항목 미기록 · 추가 자료 필요 · 담당자 확인 대기 · 기타**입니다. **분류 추가·삭제**에서 직접 만든 분류도 사용할 수 있습니다. 이름은 40글자 이내이며 빈 이름·중복 이름은 받지 않습니다.

분류 목록은 이 브라우저의 모든 데이터 파일에서 함께 사용합니다. 분류를 삭제하면 이 브라우저에 저장된 해당 분류의 메모를 **미분류**로 옮기고 내용·확인 상태는 보존합니다. 기존 메모도 분류를 선택하기 전에는 미분류로 표시합니다. 기본 분류 역시 삭제할 수 있으며 새로고침해도 삭제한 분류가 다시 생기지 않습니다.

차트 아래의 **확인 불가 모아보기**를 펼치면 현재 데이터 전체의 확인 불가 항목을 분류별로 볼 수 있습니다. 건수는 측정 수가 아닌 체크리스트 항목 수입니다. 측정 기록의 검색·필터와 별도로 표시하며, 현재 원본과 기준에 유효한 상태만 포함합니다. 분류 필터, 20개씩 페이지 이동, 메모, **측정 기록 열기**를 제공합니다.

**이유 CSV 저장**은 모아보기의 선택 분류 전체 항목을 내보냅니다. 현재 페이지에만 제한하지 않습니다. 결과 CSV의 `followUpChecklist`에는 `reasonCategory`가 포함되고, TXT·Markdown 보고서에는 분류별 모아보기가 포함됩니다. 결과 CSV는 현재 검색·필터 범위이고, 보고서는 상단에서 검색·필터 결과 또는 체크한 기록을 선택합니다. 저장 방식은 브라우저 로컬 저장소이며, 기기 사이의 자동 동기화나 CSV를 통한 검토 상태 자동 복원은 제공하지 않습니다.

## CSV 입력 형식

- UTF-8 CSV를 사용합니다. BOM, CRLF/LF, 인용된 쉼표·따옴표·줄바꿈을 지원합니다.
- 열 이름은 [입력 양식](data/demo-records.csv)과 동일한 영문 키입니다. 순서는 바뀌어도 됩니다.
- `batchId`, `measurementId`, `viscosity`, `unit` 열은 필요합니다. 나머지 열이 없거나 비어 있으면 기록 누락으로 표시합니다.
- 배치·측정 번호가 없거나 측정 번호가 중복되면 입력을 거부하고 기존 데이터를 유지합니다.
- 점도 단위는 `mPa·s`, `cP`만 지원합니다. 둘은 수치가 같고, 다른 단위는 자동으로 변환하지 않습니다.
- 숫자에는 단위를 붙이지 않습니다. `1,200` 대신 `1200`을 입력합니다. 소수점은 `.`입니다.
- 측정 일시는 시간대가 있는 ISO 형태를 사용합니다. 예: `2026-10-02T09:00:00+09:00`.
- 첫 버전 제한: 20MB 이하, 최대 20,000행. 지원하지 않는 추가 열은 검토에 사용하지 않습니다.

각 항목의 이름은 상세 화면에서 볼 수 있고 [데이터 사전](data/데이터_사전.md)에도 정리합니다. pH·염·특정 첨가제 등의 제품별 항목은 아직 추가하지 않았습니다.

## 기준과 기록의 의미

초안 기준은 실제 시험 SOP가 아닙니다. 화면에서 숫자 조건을 수정할 수 있습니다. 온도 평형 완료, 침지 표시 준수, 기포 육안 미관찰, 교정·표준액 점검 확인 등의 상태 요건은 현재 데모 규칙에 고정되어 있습니다. 실제 제품으로 전환하려면 상태 요건도 해당 방법에 맞춰 바꿔야 합니다.

모든 40개 항목의 기록 유무를 확인하지만, 모든 항목에 물성 판단 규칙이 있는 것은 아닙니다. 고분자 등급·용매·계량 질량·투입 순서·육안 균일성·보관 조건·추가 교반·휴지 시간·장비 ID 등은 이번 버전에서 기록 조회와 수동 검토 대상입니다. 조성의 질량 수지나 균일성 판정을 자동으로 확정하지 않습니다.

제조·측정 온도 차이, 농도, 교반 속도·시간, 측정 속도·읽는 시점·시료량·스핀들·용기·토크 등은 가상 기준과 비교합니다. 조건에 문제가 있어도 표시 점도 수치의 범위 내외를 함께 보여주며 **비교 조건 확인 필요**를 붙입니다.

온도 기록 한 개가 측정 내내 온도가 유지됐다는 증명은 아닙니다. ‘육안 미관찰’도 미세 기포가 없다는 증명이 아닙니다. 교정·표준액 점검 상태는 입력된 기록을 검토할 뿐 실제 장비를 점검하거나 성적서를 검증하지 않습니다.

## 저장과 내보내기

상단의 **TXT 내려받기**는 메모장에서 읽을 수 있는 `.txt` 보고서를 내려받습니다. 코드·표 대신 한글 항목으로 적용 기준과 검토 결과, 확인 불가 분류·이유·검토 메모를 정리하며 UTF-8 BOM과 Windows 줄바꿈을 사용합니다. 옆의 **화살표**에서는 보고서 형식만 선택합니다. Markdown (`.md`)을 선택하면 버튼이 **Markdown 내려받기**로 바뀌며, 그 버튼을 눌러야 파일을 내려받습니다. 형식 선택만으로는 다운로드하지 않습니다. 선택한 형식은 검색·필터·페이지·데이터 변경 동안 유지되고 새로고침하면 TXT로 시작합니다. 그래프·PDF 형식은 후속 확장 대상으로, 현재 메뉴에는 구현된 형식만 표시합니다.

측정 기록 앞의 체크박스로 여러 기록을 고르면 **보고서에 담을 기록**이 자동으로 ‘체크한 기록’으로 바뀝니다. 검색·필터·페이지를 바꿔도 선택은 유지되며, 표 머리의 체크박스는 **현재 페이지**의 기록을 선택합니다. 상단에서 ‘검색·필터 결과’를 선택하면 기존 방식으로 보고서를 내려받습니다. 두 형식 모두 같은 범위와 기준·메모를 사용하고, 보고서 안에 범위를 명시합니다. 대상이 0건이면 보고서 다운로드를 비활성화합니다. 새로고침하거나 데이터를 새로 불러오면 보고서 선택은 초기화합니다. 결과 CSV는 현재 검색·필터 결과를 내보냅니다.

메모와 자료 확인 체크 상태는 입력할 때 브라우저에 자동 저장되므로 보고서 다운로드 버튼을 누를 필요가 없습니다. 확인 불가 메모 입력칸 아래에도 자동 저장 안내를 표시합니다.

개발 중에는 로컬 미리보기에서 기능을 먼저 수정·확인하고 기능별 GitHub 브랜치·커밋·merge를 진행합니다. 공개 사이트에는 사용자가 배포를 요청할 때 변경 내용을 모아서 반영합니다.

- 기준과 메모는 이 브라우저의 로컬 저장소에 보관됩니다. 다른 브라우저·기기와 공유되지 않습니다.
- 메모는 데이터 파일의 내용 식별자와 측정 번호로 구분합니다. 파일 내용이 바뀌면 별도 데이터로 취급합니다.
- CSV 업로드 파일 자체는 저장하지 않습니다. 새로고침 후 같은 파일을 다시 불러오면 해당 메모를 사용할 수 있습니다.
- CSV에는 원본 항목, 기준 버전, 전체 기준 JSON, 상태·이유·메모가 포함됩니다.
- TXT·Markdown 보고서에는 현재 기준 전체와 검토 요약·측정별 결과·메모가 포함됩니다. 원본 CSV와 함께 보관합니다.
- 내려받기는 필터된 기록만 포함합니다. 전체를 저장하려면 검색·필터를 초기화합니다.
- CSV의 수식으로 해석될 수 있는 문자 입력에는 안전용 작은따옴표를 붙입니다. 해당 문자는 출력 시 달라질 수 있으며 원본 파일을 별도로 유지해야 합니다.

로컬 저장과 다운로드는 변경 불가능한 감사추적, 규제 적합성 또는 회사의 승인 절차를 대신하지 않습니다.

## 검증과 데이터 재생성

```powershell
npm test
npm run generate
```

재생성은 저장된 합성 입력·기대 결과·예시 보고서를 덮어씁니다. 원본 시연 파일을 직접 수정했다면 먼저 따로 보관하세요. 기준 변경만으로 데이터를 재생성할 필요는 없습니다.

브라우저 검증은 개발 도구 Playwright와 Chrome이 있는 환경에서 별도로 수행합니다. 앱을 실행한 뒤 아래 명령을 사용합니다.

```powershell
# playwright 패키지가 설치된 환경
node tests/ui-smoke.cjs
```

다른 위치에 설치된 패키지를 사용하면 `PLAYWRIGHT_PACKAGE` 환경 변수에 패키지 경로를 지정합니다. Chrome 경로는 `CHROME_PATH`로 지정할 수 있습니다. 스크린샷과 실행 결과는 Git에 포함하지 않는 `test-artifacts`에 생성됩니다.

단일 파일 검증은 `PORTABLE_TEST` 환경 변수를 `1`로 지정한 뒤 같은 브라우저 검증을 실행합니다. 이때 서버 주소 대신 실제 `file:` 경로로 열어 기능을 확인합니다.

후속 기능은 [개발 계획](../기획서/05_고분자_점도_검토_개발계획.md)에 정리했습니다.
